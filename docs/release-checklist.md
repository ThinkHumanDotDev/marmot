# Release checklist

Marmot is released by pushing a `vX.Y.Z` tag. The tag triggers [`release.yml`](../.github/workflows/release.yml),
which:

1. checks that the tag matches `version` in `package.json`;
2. builds `docker/Dockerfile` for `linux/amd64` and `linux/arm64` and pushes it to GHCR with OCI labels and
   annotations (docker/metadata-action):
   - final release `v0.1.0` → `ghcr.io/thinkhumandotdev/marmot:0.1.0`, `:0.1` and `:latest`;
   - prerelease `v0.2.0-rc.1` → only `:0.2.0-rc.1` (no `:0.2`, no `:latest`);
3. smoke-tests the **published** image: checks the multi-arch manifest, pulls it through
   `docker/docker-compose.yml` (+ `docker-compose.smoke.yml` for ports) and runs
   [`scripts/smoke-test.sh`](../scripts/smoke-test.sh) – the same checks as the CI compose job (health
   endpoints through Caddy, socket.io handshake, security headers, worker boot, container healthchecks, a
   single `MARMOT_ROLE=all` container with a clean shutdown);
4. creates the GitHub Release with notes generated by [git-cliff](https://git-cliff.org) from
   [`cliff.toml`](../cliff.toml) (marked as prerelease for `-rc`/`-beta` tags).

Nothing is tagged or pushed automatically from a developer machine; the steps below are manual.

## 1. Prepare

- [ ] `main` is green in CI (Postgres and MongoDB, Docker image & compose smoke).
- [ ] Milestone issues for the version are closed or moved.
- [ ] Choose the version ([SemVer](https://semver.org); while `0.x`, breaking changes bump the minor).
- [ ] On an up-to-date `main`:

  ```bash
  git switch main && git pull --ff-only
  pnpm release:prepare 0.1.0
  ```

  [`scripts/release.sh`](../scripts/release.sh) sets `package.json` `version`, the default image tag
  (`${MARMOT_VERSION:-0.1.0}`) in `docker/docker-compose.yml` and regenerates `CHANGELOG.md` with
  `pnpm dlx git-cliff@2` (set `GIT_CLIFF` to use another binary). It prints the next commands and does not
  commit, tag or push.

- [ ] Review `CHANGELOG.md`. Commit messages are the source: fix wording by editing `cliff.toml` (grouping,
      skips) rather than the generated file, or accept small hand edits for this release only. Call out
      breaking changes and required manual steps (new required env vars, migrations that take long).

## 2. Release PR

- [ ] Commit on a branch and open a PR titled `chore(release): vX.Y.Z` (this exact form is skipped by the
      changelog):

  ```bash
  git switch -c chore/release-0.1.0
  git add package.json docker/docker-compose.yml CHANGELOG.md
  git commit -m "chore(release): v0.1.0"
  git push -u origin chore/release-0.1.0
  ```

- [ ] Wait for CI, squash-merge.

## 3. Tag

- [ ] Tag the merge commit on `main` and push the tag:

  ```bash
  git switch main && git pull --ff-only
  git tag -a v0.1.0 -m "v0.1.0"
  git push origin v0.1.0
  ```

- [ ] Watch the **Release** workflow (Actions tab): `image` → `smoke` → `release`. If `smoke` fails, the
      image is already on GHCR but no GitHub Release is created; fix forward with a patch version rather than
      moving the tag.

## 4. Verify the published image

- [ ] First release only: in GHCR (**Packages → marmot → Package settings**) set the visibility to
      **Public** and link the package to the repository, otherwise `docker pull` requires a login.
- [ ] Clean `docker compose up` smoke on a machine (or VM) without a checkout or cached images (while the
      repository is private, copy `docker/docker-compose.yml`, `docker/Caddyfile` and `docker/.env.example`
      from the tag instead of using the raw URLs):

  ```bash
  mkdir marmot-smoke && cd marmot-smoke
  base=https://raw.githubusercontent.com/ThinkHumanDotDev/marmot/v0.1.0/docker
  curl -fsSL -O "$base/docker-compose.yml" -O "$base/Caddyfile"
  curl -fsSL "$base/.env.example" -o .env
  sed -i "s/^PAYLOAD_SECRET=.*/PAYLOAD_SECRET=$(openssl rand -hex 32)/" .env
  docker image rm ghcr.io/thinkhumandotdev/marmot:0.1.0 2>/dev/null || true
  docker compose pull
  docker compose up -d --wait
  curl -fsS http://localhost/api/health                       # {"ok":true,...}
  curl -fsS 'http://localhost/socket.io/?EIO=4&transport=polling'   # contains "sid"
  docker compose logs worker | grep 'worker booted'
  docker compose ps                                           # web, realtime healthy
  ```

  Open `http://localhost`, complete the first-run setup, create an HTTP monitor and see heartbeats arrive
  live. Then clean up with `docker compose down -v`.

- [ ] On an arm64 host (Apple Silicon, Raspberry Pi, Graviton) repeat at least `docker compose up -d --wait`
      and the health check; CI only runs the published image on amd64.
- [ ] `docker buildx imagetools inspect ghcr.io/thinkhumandotdev/marmot:0.1.0` lists `linux/amd64` and
      `linux/arm64`; `:latest` and `:0.1` point at the same digest (final releases only).

## 5. Announce

- [ ] Review the generated GitHub Release notes; add upgrade notes or highlights at the top if needed.
- [ ] Update [deployment docs](deployment.md) if the upgrade needs manual steps.
