## [0.1.0] - 2026-10-05

### Features

- **auth:** Generic OIDC single sign-on via openid-client ([#43](https://github.com/ThinkHumanDotDev/marmot/pull/43))
- **auth:** First-run setup wizard, instance settings and signup controls ([#42](https://github.com/ThinkHumanDotDev/marmot/pull/42))
- **collections:** Organizations, memberships, invitations and org-scoped RBAC ([#38](https://github.com/ThinkHumanDotDev/marmot/pull/38))
- **engine:** BullMQ polling engine, heartbeat state machine and core monitor types ([#39](https://github.com/ThinkHumanDotDev/marmot/pull/39))
- **monitors:** Monitor create/edit form, detail page and org-scoped mutation routes ([#46](https://github.com/ThinkHumanDotDev/marmot/pull/46))
- **notifications:** Notification channels collection, provider pipeline and first 10 providers ([#47](https://github.com/ThinkHumanDotDev/marmot/pull/47))
- **notifications:** Second wave of notification providers ([#49](https://github.com/ThinkHumanDotDev/marmot/pull/49))
- **realtime:** Socket.io server, Redis emitter and live dashboard wiring ([#45](https://github.com/ThinkHumanDotDev/marmot/pull/45))
- **stats:** Time-series aggregation, uptime calculator and retention ([#40](https://github.com/ThinkHumanDotDev/marmot/pull/40))
- **status-pages:** Status pages, incidents, public page and RSS ([#48](https://github.com/ThinkHumanDotDev/marmot/pull/48))
- **ui:** Shadcn/ui design system, app shell, auth pages and Zustand stores ([#37](https://github.com/ThinkHumanDotDev/marmot/pull/37))
- **ui:** Members, invitations and organization settings ([#44](https://github.com/ThinkHumanDotDev/marmot/pull/44))

### Bug fixes

- **docker:** Bundle the server entrypoints with esbuild instead of loading TypeScript at runtime
- **stats:** Convert the heartbeat time to a Date before recording stats
- **stats:** Align the stats listener with the engine's heartbeat event types

### Build and CI

- Fix Mongo compose override, group action updates and bump action majors
- Run integration tests on a separate database and bound the migrate step
- Wait for the worker to boot in the compose smoke test instead of asserting immediately

### Maintenance

- **infra:** Harden Docker image, compose, Caddy, health checks and dev tooling ([#41](https://github.com/ThinkHumanDotDev/marmot/pull/41))
- **test:** Stop pinning the shared marmot_test database in .env.test
- Scaffold Marmot on Payload CMS 3 and Next.js
